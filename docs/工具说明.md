# 联合复盘工具使用说明（drayage_review）

本工具把"船侧、堆场、短驳三份记录"合并为**一个联合可行箱程模型**，在同一套约束上
做反事实复盘，避免各方按本地记录各选一条时间线后把差额相加。

## 1. 核心方法

### 1.1 可行箱程而非本地时间线

每个箱程有 4 个不确定交接时刻（船侧交接、放行、短驳接手、交付），证据只给出区间
`[lo, hi]`；另有 3 段专占设施服务：

| 服务 | 设施 | 覆盖/跟随关系 |
| --- | --- | --- |
| 开放泊位 | 船口 | 服务窗必须覆盖船侧交接，并在船侧截单前完成 |
| 堆场复核 | 公用/专线 | 服务窗必须覆盖放行 |
| 短驳班组 | 全港 | 船侧交接与放行均完成后才可装运，完成不晚于交付 |

每段服务必须**整体落在**该箱 `barriers` 的窗口内；共享设施同一时刻最多 `units` 个
箱程占用（见 `capacity.json`）。模型用混合整数规划（scipy/HiGHS）求：

1. 一条**政策箱程**：先最小化总交付时刻，再按箱序最小化服务开始时刻（确定性平局）；
2. 每个时刻/窗口在联合可行域内的最小、最大值（**联合可行包络**）。

证据只给区间、不挑单点；窗口的合同计时用包络 `[lo, hi]`，争议额 = 上界与下界之差。

### 1.2 不做"各选一条时间线相加"

迟延归因对每个设施做三类**边际反事实**（都在同一联合模型上重解）：

* 单独放松该设施的箱侧窗口起点；
* 单独解除该设施的共享名额限制；
* 两者同时放松。

判定：

* 只有窗口或名额之一放松就能减少交付 → **明确可归因**（窗口/名额分别列示）；
* 必须两者同时放松才有减少 → **仅联合范围**，证据不足以在班组/设施间拆分，
  份额留空（`joint_only_relief`），禁止单方认领；
* 联合放松仍无改善 → 迟延由交接证据区间本身决定（典型：接驳快了两小时，
  但堆场更晚才放行，船期减时为零）。

### 1.3 无可行箱程的隔离

时序证据冲突到不存在可行箱程时（如泊位窗口无法覆盖船侧交接），逐箱定位并隔离：
该箱的全部计价项目标记"拦下"并保留原因，同船次其他箱照常求解与复盘。

## 2. 命令

```sh
# 生成一次联合复盘（--as-of 控制账期可见证据，含柜台更正的生效日）
python3 -I drayage_review_cli.py run --as-of 2026-06-07 --out out/r2

# 按箱查共享等待、联合可行包络与边际归因
python3 -I drayage_review_cli.py box --box BX03 --run out/r2

# 按船次比较 baseline / 单项补救 / 组合补救
python3 -I drayage_review_cli.py vessel --vessel V2 --run out/r2

# 按合同批次追可计费时间、争议差额与书面确认额度
python3 -I drayage_review_cli.py contract --contract Q3 --run out/r2

# 与上一账期运行对比，差额按三类成因分解
python3 -I drayage_review_cli.py reconcile --previous out/r1 --current out/r2
```

每次 `run` 在输出目录落盘 `manifest / fleet / attribution / billing / remedies /
dataset_snapshot` 六个 JSON，作为不可变运行快照，供后续账期对账与审计。

## 3. 补救与确认单规则

* 同一批箱、同一组运行条件下重解 baseline、每个单项、以及作用于同箱的组合；
  组合收益由联合重排自然得出——搬运位释放后可能被别箱占用，或被已预告的船侧
  截单吃掉，不做本地节省相加。
* 单方分配只在"该设施是唯一边际原因且共享名额未被占用"的明示假设下成立；
  证据不能区分的份额保留为区间，不硬填。
* 临时补助资格同时要求：存在可核实减时（保守口径 > 0）**且**合同保留额度有余量；
  "已确认"与"待调整"额度都占用保留额度。
* "待调整"确认单冻结：项目后来确认时长更短，已承诺额度不会凭新测算自动转给别家，
  须双方书面确认。
* 同一 `(箱, 补救)` 出现多张确认单 → 重复认领拦截；同一箱被多张确认单计为收益来源
  时给出合并提示，只允许按反事实增益认领一次。

## 4. 账期滚动的差额三成因

`reconcile` 逐合同行对比相邻两次运行：

| 成因 | 触发条件 |
| --- | --- |
| observation 观察更完整 | 该箱有新登记更正/观察；或同船次新证据经共享名额/班组能力联动改变联合可行域 |
| attribution 责任解释变化 | 证据区间与可行域未变，政策箱程/可分配份额调整 |
| remedy 补救实际省时 | 反事实情景中可核实减时发生变化 |

无实质变化的行折叠显示且不进入成因合计；拦截/恢复的计价项目原样结转。

## 5. 已知数据特征（当前 data/）

严格执行共享名额后，V1、V4 的 4 个短驳班组服务在同一时段高度重叠而能力只有 2 个
单位，相关箱程无可行排程、按规则拦下；这是"班组能力不足"的如实反映，而非模型错误。
当前补救方案在反事实重解中均未省出可核实交付时间（改善被证据区间或下游环节吸收），
因此确认单 a1/a3 会被提示复核依据、临时补助不成立——工具不会为了凑收益而填数。
